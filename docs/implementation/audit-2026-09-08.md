# Project audit — 2026-09-08

Scope: the whole repository against its own documentation. Every claim below was produced by running
the check or reading the file named beside it. Where a check disproved a suspicion — including two of
this audit's own first-pass findings — that is recorded, because a false finding is worse than none.

Read with [START-HERE.md](../START-HERE.md). This is a snapshot, not a gate; the gates are
`pnpm check:affected` and `pnpm launch:code`.

## 1. Verdict

The repository is consistent with its documentation. Every contour the registry declares exists in the
source at the state it claims, every declared route is accounted for, the migration stream is
sequential and additive, and no product path returns success where it cannot deliver.

Four defects were found, all in ownership metadata rather than in product code, and all minor: two
manifest rows point at a file that no longer exists, 31 of 73 scripts are unclaimed, one document is
unclaimed, and the gate that validates ownership cannot detect any of these because it never compares
the manifest to the disk.

For whoever takes this project forward: **the product is in the state the documents say it is.** What
needs attention is the map of who owns which file, and one gate that does not check what it appears to.

## 3. Two first-pass findings that were wrong

Recorded because the method matters more than the tally.

A first pass reported that `packages/cloudflare-evidence` and `packages/cloudflare-projection` were
entirely unowned, and that the registry and governing documents were unclaimed. Both came from parsing
`docs/agent-work/manifest.json` alone.

Running `check-work-packets.mjs` disproved them: it reports **44 packets and 391 claims** where the
manifest alone yields 37 and 338, because ownership is the union of the manifest **and** the
`docs/agent-work/ER-*.md` packet documents. `ER-38-governed-projection-generation-execution.md:16`
claims `packages/cloudflare-projection/**`; `implementation-status.json` and `slice-gates.md` are
likewise claimed there.

An attempted fix based on the false reading — adding `packages/cloudflare-projection/src/**` to ER-24 —
was rejected by the gate as an overlap with ER-38 and reverted. **Both findings are withdrawn.**

## 4. Findings

### 4.1 Two manifest rows point at a file that does not exist

`docs/agent-work/manifest.json` still lists `apps/eliotr-core/src/projection-delivery-handler.ts` and
its test under ER-24. #141 moved both into `packages/cloudflare-projection/` to restore Worker budget
headroom, and the rows were not updated. The path resolves to nothing:

```
ls: cannot access 'apps/eliotr-core/src/projection-delivery-handler.ts': No such file or directory
```

The files are correctly claimed at their new location by ER-38's packet document, so this is stale
duplication rather than an ownership gap. **Fixed in this change** by removing the two dead rows from
both `manifest.json` and `ER-24-worker-composition-do-queue-and-schedules.md` — nothing is reassigned,
because nothing needs to be.

Removing them from the manifest alone made the gate fail with *"packet document owns path absent from
manifest"*, which is the gate working correctly: it enforces agreement between the two sources. It
simply has no opinion about a path that is dead in both.

### 4.2 31 of 73 scripts are unclaimed

Counted against the union of manifest and packet documents. The unclaimed set includes live gates
(`check-gemini-integration.mjs`, `check-cloudflare-usage-preflight.mjs`), the `test-usage-*` family,
and `test-access-runtime-*`.

**Not fixed — deliberately.** Assigning 31 files would mean inventing ownership for most of them, which
is the failure mode the manifest exists to prevent. It needs an owner's decision, not an integrator's
guess.

One entry is mine: `scripts/check-docs-index.mjs` was added in #109 without a claim. That is drift I
introduced, not inherited.

### 4.3 `docs/START-HERE.md` is unclaimed

The single entry point every brief cites is claimed by no packet. Added in #109, also mine. **Not
fixed**, same reason as 4.2 — although this one has an obvious candidate in ER-00, which owns the rest
of the documentation scaffolding.

### 4.4 The ownership gate cannot detect 4.1–4.3

`scripts/check-work-packets.mjs` validates manifest/document agreement, non-empty `owned_paths`,
duplicates within a packet, and overlapping claims between packets. It never calls `existsSync`, and it
never enumerates the tree to find unclaimed files. That is exactly why a row pointing at a deleted file
survived a green `check:affected` on every merge since #141.

Two checks would close it: every `owned_path` must resolve on disk, and every source file must be
claimed by at least one packet. **Not fixed** — the script is ER-00-owned, and a gate that would
immediately fail on 4.2 is a change whose blast radius belongs to its owner.

The gate did, however, catch two mistakes during this audit — a fix that would have created an
overlapping claim (§3), and an incomplete fix that removed rows from the manifest but not from the
packet document (§4.1). Within what it checks, it works.

### 4.5 One register number was wrong

`gap-register.md` credited `retrieval.test.ts` with 13 passing cases; the file contains 14 `it(` blocks.
Found during the Q5 checkpoint, verified by counting, **fixed in #146**.

## 5. Observation, not a defect

`gap-register.md` is claimed by two packet documents (ER-00 and ER-40) while
`execution-contract.md:54` requires *every* implementation change to update it — and it was modified 15
times in the last 24 hours by checkpoints that were right to do so. The gate tolerates this and passes.
It is a modelling oddity rather than a violation: a register that every change must touch is not
usefully described as owned. Worth deciding deliberately rather than leaving implicit.

## 6. Disclosure

This audit edits `docs/agent-work/manifest.json`, which is ER-00-owned, for finding 4.1 only — the
narrowest possible change, removing two rows that point at a deleted file. Everything requiring a
judgement about who *should* own a path is reported and left alone.

That is the standard applied to the swarm all session: cross a boundary only for something demonstrably
broken, make the smallest change that fixes it, and disclose it rather than let it pass as routine.
