# Eliot Research: working rules

Read [the current architecture](docs/architecture/ELIOT_RESEARCH.md), choose one result from
[the implementation plan](docs/implementation/backend-entrypoints.md), then read only relevant source
and nested instructions. Current owner instructions and the selected architecture supersede contradictory
legacy packets, audit checklists and older ADR requirements. They do not authorize a production reset.

## Write less, maintain one implementation

- Keep the selected product: sources/projects, cited answers/reports, Wiki/Inbox and connected-agent tasks.
  One Worker, existing React/Vite, one owner client, D1/R2, native search and Workflows. No Astro expansion.
- Change internal APIs and their callers together. Delete replaced code, exports, decoders, fixtures,
  dependencies and obsolete instructions. A forwarding wrapper is not completed consolidation.
- No speculative federation, bilateral source-owner transfer, seven-domain residency machinery,
  backup/restore platform, custom index generation registry, proof/signature chain or second agent engine.
  Existing reachability does not make an unselected feature mandatory. Keep ordinary downloads.
- No compatibility for hypothetical clients, unpublished prototypes or old tests. Preserve actual user
  content/results with a one-time conversion or ordinary stored locator. An old report needs a reader,
  not its historical executor. Temporary adapters leave with their named actual consumer.
- No new module, table, abstraction, protocol version or dependency without a selected behavior or a concrete
  implementation it replaces. Prefer direct functions and cohesive modules; do not split packages to game counts.
- Use [the language contract](docs/architecture/LANGUAGE_RUNTIME_CONTRACT.md). Rust operations need actual
  callers; no mandatory all-family port, per-call hash envelope or permanent TS/Rust/SQL duplicate engines.

## Necessary boundaries

Authenticate at ingress with the existing Access/verifier path; protect alternate entry routes too.
Connected agents keep explicit operation/project access. Never treat an asserted identity header as verified.
Keep credentials server-side, normal TLS/secret handling, safe rendering and practical input/memory limits.
No custom cryptosystem or repeated authorization/proof chain on every owner list or draft.

D1 owns metadata and atomic expected-revision changes; R2 owns stored bytes. Search returns candidates;
the existing evidence resolver maps citations to admitted revisions and exact ranges. Use stored content
checksums only where they serve actual identity/integrity. A failed observation is not absence or a match.
Do not create a second citation store. Source detach and source deletion are different operations.

Keep the original mutation/run/paid-attempt identity, cancellation and spend bound. Reconcile uncertain
effects; reconnect/status reads never dispatch another model call. No network/model/R2 work in a D1
transaction. Retire old executors after settling their actual running attempts, not after replaying history.
Source cleanup does not silently delete data, change live credentials or apply canceled migrations.

## One manager, one checkout

Reuse the manager's existing branch/checkout. Leaves receive one outcome and exact disjoint files;
shared roots, manifests, routes and migrations are serialized by the manager. Leaves create no worktrees.
Use subagents only when a real execution tool is available; do not claim delegated work or independent review
that did not occur. Preserve concurrent work and publish with the expected branch head, without force overwrite.

No JSON claim, claim-only commit, ancestry ceremony, packet lock, owner-count quota or repeated approval
is needed for ordinary authorized development. ER packets locate historical source; they are not a queue.
The plan includes removal of their obsolete tooling, not permanent maintenance as an optional product.
A blocker stops its affected operation only. After two failed approaches, diagnose and change approach.

## Verification and reporting

Implement first. During this phase run scoped TypeScript compile/lint; changed Rust gets scoped compile
and minimal Clippy; changed SQL gets the existing affected schema/query check. Tests and product acceptance
come after the product is assembled. Do not create a test-writing/coverage/mutation campaign before coding.
Existing automatic CI remains separate; skipped or unrun checks are never PASS.

For a documentation change, check the actual diff and links. Update the relevant current document instead
of adding another audit programme, diary, receipt inventory or mandatory status manifest. The PR needs the
result, removed implementations, checks actually run and remaining limitations. No inflated completion claims.

For rendered UI work, use the existing Material playbook and execution map only for selected behaviors.
The owner reviews the integrated final UI, not every internal checkpoint. React cutover includes standalone
Inbox/recovery and old service-worker retirement; an old rollback artifact does not justify two maintained UIs.
[Branch discipline](docs/implementation/branch-discipline.md) covers publication. No deploy or data deletion
is implied by this documentation work.
